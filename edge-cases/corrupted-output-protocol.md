# Edge-case protocol: corrupted or unassessable outputs

When the artifact is corrupted, missing, or the trace is incomplete, you
cannot score quality. Score what you can and say so plainly.

## Corrupted file

1. Confirm the corruption: try opening in the native app and one
   alternative (e.g. PowerPoint and LibreOffice).
2. Do not guess at content from the trace narrative.
3. Write the feedback on the run information only: attempts, runtime,
   errors, validation steps (or lack thereof).
4. Verdict: **Not assessable from the provided information.**
5. Recommendation: re-run required before any quality verdict.

## Missing trace

1. Note exactly what is missing (runtime, validation, follow-up questions).
2. Assess the artifact on its own merits, but mark every run-dependent
   dimension as unknown.
3. Verdict: at best **Partially successful** — never Successful without a
   trace, because validation discipline cannot be confirmed.

## Partial trace

1. Use what exists; mark the gaps explicitly ("validation steps not
   confirmed", "fresh folder not confirmed").
2. Do not fill gaps with assumptions.

## Rule

An edge case is a report about the run, not a verdict on the output. Keep
the two separate and the feedback stays honest.
